# MASTER PROMPT — ACADEMIC PORTFOLIO & DIGITAL CV SYSTEM

## Role and Mission

You are a Principal Laravel Engineer, Senior React/TypeScript Architect, UI/UX Designer, Accessibility Specialist, and Software Quality Engineer.

Build a complete, professional, enterprise-quality **Academic Portfolio & Digital Curriculum Vitae Management System**.

The application represents an individual academic, professor, researcher, or professional. It is not a university administration portal.

The visual design should follow a **University Corporate** direction: institutional credibility, sophisticated typography, formal academic presentation, modern interactions, structured information, and excellent usability.

The project must be designed for long-term maintainability, extensibility, reusable components, and future integrations.

**This iteration is frontend-first. DO NOT implement a database, ORM-backed persistence, or production authentication.**

Create functional public pages and a realistic, clearly labeled demonstration dashboard using Laravel PHP configuration files, mock data providers, and React state.

Do not create a static-only website. Interactions should work with mock data wherever feasible.

---

# 1. Technical Stack

Use the latest compatible stable patch releases of:

- Laravel 13.x
- PHP 8.3 minimum; prefer PHP 8.4 or 8.5 where supported
- Inertia.js 3.x, if compatible with the selected Laravel starter kit
- React 19
- TypeScript in strict mode
- Tailwind CSS 4
- shadcn/ui
- Radix UI primitives where appropriate
- Vite
- Lucide React icons
- Laravel Pint
- Pest for PHP testing
- Vitest + React Testing Library for frontend tests
- Playwright for end-to-end browser testing
- ESLint and Prettier
- Zod for validation of frontend form data when beneficial

Optional dependencies, install only when needed:

- React Hook Form for complex forms
- TanStack Table for advanced dashboard tables
- Recharts for statistics and visualizations
- Motion for React for meaningful animations
- Embla Carousel for accessible carousels
- DOMPurify for rendering trusted rich-text workflows safely, if absolutely necessary

Before installing dependencies:

1. Review existing project files.
2. Verify compatibility with Laravel 13 and React 19.
3. Inspect the official Laravel React starter kit.
4. Prefer maintained official dependencies.
5. Avoid redundant frameworks and overlapping libraries.
6. Do not use deprecated Laravel Breeze or Jetstream scaffolding.
7. Do not install Livewire, Alpine.js, Vue, or a second frontend framework.
8. Record major package versions and relevant technical decisions.

Use Laravel's official React starter kit as the reference starting architecture, but remove or disable unnecessary database-dependent authentication scaffolding for this UI-only phase.

Do not automatically create authentication tables, migrations, or default database-dependent routes.

# 2. Core Development Constraints

These requirements are non-negotiable:

- No database connection.
- No database migrations.
- No Eloquent models.
- No database seeding.
- No actual credential verification.
- No production authentication or authorization.
- No real user accounts.
- No permanent write operations.
- No remote API dependency for basic rendering.
- No real document repository.
- No fake security guarantees.
- All user-facing content must be English.
- Reusable architecture must be preferred over page-specific duplication.

The public website and dashboard must function without requiring MySQL, PostgreSQL, SQLite, or another database service.

Mock data should originate from Laravel-side PHP configurations and typed providers.

React may use local component state for temporary demonstrations. Changes may reset when the page is refreshed.

Where persistent behavior is eventually required, expose an interface suitable for a future repository or API integration.

DatabaseAcademicContentRepository

- React components do not know where records originate.
- Controllers remain thin.
- Data transformations are centralized.

- Dates use a consistent format.
- IDs are stable.
- All sample data is clearly labeled demonstration data.
- Visibility filtering is applied before sending props.
